# AGENTS.md

This file provides guidance to coding agents working with code in this repository.

## Status

The workspace, contract, API, SQLite persistence, validated Socket.IO transport, authenticated admin surfaces, design-complete web screens, and end-to-end mediasoup audio are implemented. Media uses a worker pool and one router per active event; guests keep one connection for the event. Settings storage remains unresolved.

Keep this file current as decisions are made.

## Layout and commands

- `packages/contract` — hand-written Zod schemas and `createRoute()` definitions. Never built: every export points at TypeScript source and consumers compile it. `src/socket` holds the socket event contract behind the `./socket` subpath export and is **not** re-exported from the root barrel, which pulls in Hono via `./openapi`; browser clients import `@linguacast/contract/socket`. `src/schemas/patterns.ts` holds the bare regexes (`PIN_PATTERN`, `SLUG_PATTERN`, `SEMVER_PATTERN`), the three drawn password rules (`PASSWORD_MIN_LENGTH`, `PASSWORD_NUMBER_PATTERN`, `PASSWORD_SPECIAL_PATTERN`) and the separate request-size ceiling (`PASSWORD_MAX_LENGTH`) behind `./patterns` on the same terms — one source for the server's setup schema and the web's live validation. `src/page-titles.ts` likewise sits behind `./page-titles`, keeping public event/channel browser titles identical between initial HTML and SPA navigation without pulling Hono into the browser. The maximum is not a fourth checklist line. A space counts as the special character: refusing it would reject a passphrase while accepting `password9!`. The contract imports neither `socket.io` nor mediasoup. Its tsconfig sets `"types": []` with no DOM (the React Native seam): a `node:` or DOM import in `src` must fail to compile.
- `tools/openapi-codegen` — a private package whose only job is holding `typescript@5.9.3` and exposing an `openapi-codegen` bin; `packages/contract` depends on it. Every real package pins `typescript@7.0.2`, and TypeScript 5 must remain unreachable as a binary from any package that compiles source — `pnpm why -r typescript` is the mechanical check. Reasoning and exit condition: `docs/solutions/architecture-patterns/isolate-a-legacy-compiler-behind-a-codegen-tool-package.md`.
- `apps/server` — Hono + `@hono/zod-openapi`. `app.ts` builds the app without listening; `index.ts` owns the listener. `defaultHook` must be passed to *every* `OpenAPIHono` instance that registers routes — it is not inherited by sub-apps.
- The production SPA keeps every Vite output file static except `index.html`. `http/spa.routes.ts` reads that file once at boot, requires the single `linguacast:metadata` marker pair from `apps/web/index.html`, and replaces only its four escaped title/description tags. Exact event and channel URLs get indexed SQLite lookups plus event, listener or speaker metadata; missing/disabled events and channels return the same shell with 404, and a stale non-empty speaker code returns it with 403. The speaker code is compared, never rendered. After React takes over, both public route components call `useDocumentTitle` with the same contract formatters; leaving them resets the tab to `LinguaCast`. These page lookups share the API's public rate-limit buckets, so an invalid browser navigation costs one token for the document and another when the SPA performs its API lookup. Every rendered shell is `no-cache`; real `/assets/*` files remain immutable. A missing web build is normal development configuration, while a present build with no usable index is fatal.
- `apps/server/src` is split by dependency direction. `core/` is the domain: it must not import `hono`, `@hono/zod-openapi` or `socket.io`, and must not reach sideways into `http/` or `socket/`, but it may import `drizzle-orm`, `better-sqlite3` and later `mediasoup`. `http/` holds every Hono-coupled module; `socket/` every Socket.IO-coupled one, split into `socket/lib/` for plumbing and `socket/handlers/` for per-feature events. `lib/` is what has neither domain knowledge nor transport coupling — `problem.ts`, `rate-limit.ts`, `semver.ts`. `db/` keeps its own conventions. The boundary is enforced by `core/boundary.test.ts`, a source-text scan that fails on a forbidden specifier, relative paths included: `docs/solutions/architecture-patterns/guard-a-layer-boundary-with-a-self-testing-import-scan.md`. File a module by what it is, not by the directory its only consumer occupies.
- Directories name the role; filenames name the entity plus a role suffix — `.service.ts`, `.mapper.ts`, `.routes.ts`, `.middleware.ts`, `.handlers.ts`. A module whose stem is already unique and role-descriptive takes no suffix: `codes.ts`, `access.ts`, `presence.ts`, `handshake.ts`, `on.ts`, `rooms.ts`, `types.ts`. Tests stay colocated as `<module>.test.ts`.
- `core/media/` holds the mediasoup layer: `config.ts` (codecs, listen infos, ICE servers), `workers.ts` (the pool), `room.ts` and `peer.ts`, `registry.ts` (one room per event, its creation slot and idle teardown), `announced-address.ts` (the announced address, resolved and kept current), `reflexive-address.ts` (a boot-time STUN binding request, for the cross-check alone), and `index.ts`, the facade every caller uses. It is a module singleton started by `startMedia()`, reached by import like `db` and never injected. `testing.ts` there starts it on fake workers so a test can drive it without binding a port.
- `core/auth/` is the account: `password.ts` (scrypt, self-describing hashes, a dummy hash for the unknown-username path, and a semaphore bounding how many 32 MB derivations run at once), `credentials.ts` (`admin.json`, an atomic write, a strict parse), `account.ts` (the module singleton started by `startAuth()`, in the shape of `core/media`), `sessions.ts` (the `admin_sessions` table) and `index.ts`, the facade. Credentials live in `admin.json` beside the database and nowhere else — never in SQLite, never in a config file a human edits — so recovery is deleting one file in the directory the operator already mounts and restarting. The file is read once at boot and held in memory: a running server cannot become unconfigured, and a file that exists but does not parse is fatal rather than silently unconfigured, which would re-open the account-claim window after a disk glitch. `createAccount` takes its claim synchronously before it hashes, for the same reason `authorizeHandshake` stays synchronous. `resetAuth()` performs the recovery in process; it exists so a test can drive a server from configured back to unconfigured.
- Sessions are rows keyed on a SHA-256 of the token, never the token: a copied database must not yield live sessions. 30 days, renewed on use only inside the last day of that life, swept at boot and deleted wherever a lookup finds one expired. The cookie is `__Host-linguacast_session` — the prefix has to be supplied at all three call sites in `http/session-cookie.ts` or the name will not match — httpOnly, `SameSite=Lax`, and `Secure` unconditionally, since `getUserMedia` already requires HTTPS.
- Auth endpoints are `/auth/*`, deliberately outside `/admin`: sign-in cannot sit behind the prefix it exists to unlock. `http/middleware/require-admin.middleware.ts` is the one `app.use('/admin/*', …)` that prefix exists for, and it checks that an account exists *before* it checks the session — between a recovery restart and the finished wizard the table still holds rows corresponding to no account. Refusals are a `Problem` with 401 and never a redirect: the caller is `fetch`, and the SPA turns the 401 into a route guard.
- Sign-in is throttled per address and never locked out. `createRateLimit` takes the statuses that cost a token (404 for the public limiter, 401 and 409 for sign-in) and the sign-in limiter has **no** shared global budget behind it: against a single account a shared budget is a lockout, because the budget check runs before the handler and a distributed guesser holding it at zero refuses the correct password too. What that budget protected — many concurrent scrypt allocations — is bounded by the semaphore in `password.ts`, which makes a caller wait rather than fail. `clientIp` trusts the rightmost `X-Forwarded-For` entry only from an address listed in `TRUSTED_PROXY_IPS`, the one environment variable this work adds; unset means the header is never believed.
- The web learns its state from one unauthenticated `GET /auth/session` (`lib/auth-queries.ts`), read by `beforeLoad` on `/`, `/admin`, `/setup` and `/login`. A 401 from any admin call invalidates that entry and then the router, so a dead session produces one redirect rather than a five-second poll failing forever; `/auth/*` is excluded, because a wrong password is not a dead session. After setup and after sign-in the entry is **seeded from the response**, not invalidated: `ensureQueryData` hands back the stale value while a refetch is in flight, and the stale value says signed out. The attempted path is carried in `?redirect=` and accepted back only as an internal router path.
- A server test file must reach `core/auth` **only** through `createTestApi()`, which returns `signInAsAdmin`, `createSession`, `resetAuth` and `SESSION_TTL_MS` from its own dynamic import. A static `import … from '../core/auth'` anywhere in a test file's graph loads `env.ts` before `createTestApi` can set `DATA_DIR`, so `credentialsPath()` resolves against the real `./data/` — the suite then provisions the operator's database and `resetAuth()` deletes their real `admin.json`. `createTestApi` passes an explicit `admin.json` path to `startAuth()` for the same reason. This is what the file's own comment about dynamic imports has always been protecting, extended to the credential file.
- Only `isOnline` moved out of `core/presence.ts`, not the whole registry: the broadcast claim is taken at the handshake, before any media exists, so it cannot live in the media layer. The claim means broadcast rights; `isOnline` means an unclosed producer exists.
- Events originating inside `core/` reach clients through `core/notifications.ts` — a typed subscribe registry over a discriminated union, at `core/` rather than `core/media/` because regenerating a PIN must evict listeners who own no media at all. `socket/index.ts` is its only subscriber and the only place that turns an eviction into a disconnect. Named notifications, not events: `core/events.service.ts` already means the domain entity. Nothing is injected into `core/`, and no handler registry maps event names to handlers as data.
- `apps/web` — Vite 8 + React 19 SPA. TanStack Router with file-based routing: a file under `src/routes/` *is* a route, and the Vite plugin regenerates `src/routeTree.gen.ts` on dev-server startup and on every change there. Nest routes as directories, not dotted filenames — `routes/admin/events/$id.tsx` — and a directory's layout route is its `route.tsx`. `routeTree.gen.ts` is generated, committed, and excluded from Biome. `tsconfig.json` must not declare `baseUrl`; TypeScript 7 removed it, and `paths` alone resolves for both `tsc` and the shadcn CLI. `src/api`, `src/socket` and `src/state` are the portable directories that lift into `packages/client-core` when the Expo app begins; everything else under `apps/web/src` is web-only. `src/lib/socket.ts` exports `connectSocket(auth)`, not a module singleton: the handshake carries the event's PIN, so one socket per page is required.
- `src/components/ui` is the shadcn CLI's target: add and update components with `pnpm dlx shadcn@latest add <name>` from `apps/web`, then `pnpm check:fix`. Deliberate customisations are allowed there but each must be recorded in this list, because a later `add` silently drops it. Current customisations: `button.tsx` carries a `pill` size (`h-12 rounded-full px-6 text-base font-semibold`) plus the admin action scale — `action`, `action-sm` and `icon-action`; `switch.tsx` checks to `foreground` and carries a `tone` prop that opts back into `primary`, plus an `lg` size (46×27 with a 21px thumb, its padding and checked offset written out because the CLI's `calc(100%-2px)` only centres the thumb at the default size's proportions); `input.tsx` carries a `shape` variant defaulting to `pill`; `dialog.tsx`'s `DialogContent` defaults to `rounded-lg p-panel` with no gap, its `DialogTitle` to `text-title` and its `DialogDescription` to `text-note`; `badge.tsx` carries a `size` variant holding the chip geometry the base used to; `button.tsx` also carries a `destructive-solid` variant, the confirming half of a destructive dialog, where `destructive` is the tint a row action carries; `select.tsx`'s trigger and `slider.tsx`'s thumb carry `cursor-pointer`; `sonner.tsx` imports `useTheme` from `@/components/theme-provider`, not `next-themes`. `card.tsx` and `label.tsx` were deleted rather than adopted: neither had an importer, and `pnpm dlx shadcn@latest add card` gets one back. The rule the list exists to enforce: **a `components/ui` default that every call site overrides is a bug, not a style** — push the product's value into the primitive and delete the constants that were cancelling it. The `rounded-[min(var(--radius-md),Npx)]` clamps on `button.tsx`'s `xs`/`sm` and `select.tsx`'s small trigger are shadcn's own spelling, are unreferenced by any app call site, and stay as they are. `add` will offer to overwrite `button.tsx` when it is pulled in as a dependency of another component (`sheet` does this) — decline that prompt. Prefer call-site classes for one-off styling. `biome.json` turns six lint rules off for that directory only (four `a11y`, `noArrayIndexKey`, `noDoubleEquals`); do not hand-fix generated files. Reasoning: `docs/solutions/conventions/customising-generated-shadcn-components.md`.
- The design's off-scale values go on the Tailwind scale, not into arbitrary utilities: the spacing scale derives from `--spacing`, so 26px is `6.5`, 18px is `4.5`, 1120px is `280`. Six values are named in `index.css`: `--spacing-gutter` (the 26px screen gutter, `px-10` from `lg`), `--spacing-shell` (the 1120px application content cap), `--spacing-panel` (the 22px panel inset), `--spacing-action-x` (17px), `--spacing-action` (38px) and `--spacing-touch` (44px). The type ramp is fifteen `--text-*` entries — `text-screen` / `text-screen-lg`, `text-hero` / `text-hero-lg`, `text-stat` / `text-stat-lg`, `text-pin` / `text-pin-lg`, `text-title`, `text-subtitle`, `text-section`, `text-body-lg`, `text-label`, `text-meta`, `text-note` — each carrying its own weight and line-height plus tracking where the design fixes one; body text is `text-sm`, and 16px, 18px and 20px are Tailwind's own `text-base`, `text-lg` and `text-xl`. There is no `text-[…]` anywhere in `apps/web/src` except shadcn's own `text-[0.8rem]` on `button.tsx`'s `sm` size; a new type size goes on the ramp or reuses a step, and near-duplicates collapse rather than earning an entry. Radius: `rounded-lg` (20px) is the panel, `rounded-md` (16px) the PIN slot, `rounded-xl` (28px) the sheet; `level-meter.tsx`'s `rounded-[1px]` peak marker is the only literal left, because one use is not a scale entry. The animations are `--animate-pulse-live`, `--animate-ring` and `--animate-ring-delayed`, all held at a resting frame under `prefers-reduced-motion` rather than removed. Where the canvas and the handoff prose disagree on an animation value, the canvas wins. Arbitrary values remain right for one-off type sizes and grid templates. Colours are never written at a call site: they are `--color-*` tokens in `index.css`, referenced by role (`text-muted-foreground`, `border-destructive`), never as a hex and never as a role borrowed to mean something else. `--live-on-muted` is the live colour *as type* on a muted surface — `live-muted` or `secondary` — and never on a `live` fill, which in dark mode is the same value. **Hover:** hover always moves toward `foreground`, in both themes, by a fixed mix — never by lowering the element's own opacity. `hover:overlay` washes a control that has a resting fill, `hover:overlay-strong` one that does not; both are `@utility` entries in `index.css` that paint the wash as a background *image*, so the control's own fill survives underneath and the result does not depend on the surface behind it. A solid `primary` fill uses `hover:bg-primary-hover` instead, which darkens in light mode and lightens in dark: `primary/80` blends toward the page and reads as disabled rather than hovered. An opacity-blended hover (`hover:bg-muted/50`, `hover:bg-card/70`) is the bug this replaces — in dark mode `muted`, `secondary`, `card` and `popover` are all one value, so a ghost control on any panel hovered to exactly the colour it already sat on. That collision is the underlying problem and the overlay routes around it rather than solving it; giving dark `--muted` its own step, the way `--accent` was already lifted one above `popover`, is a separate decision. **Focus:** a filled control takes a ring, a bare text link or a full-row link target takes a 2px outline, and the offset is 2 everywhere. **Touch targets:** a control that sits in a cluster of sibling controls bumps to 44px below `lg` and settles at 38px from `lg` — which is what `size="action"`, `"action-sm"` and `"icon-action"` do, so it comes for free. A control alone in its row does not need the bump; the named exceptions are the admin nav links and the guest back button, both sized by their surroundings rather than by the action scale. Procedure for a new value: `docs/solutions/conventions/design-values-onto-the-scale.md`.
- The setup wizard (`routes/setup.tsx`, two steps in one route) and sign-in (`routes/login.tsx`) share `components/auth/auth-card.tsx`, `password-field.tsx` and `password-checklist.tsx`; `lib/password-rules.ts` is their pure half. There is no password-change or reset surface anywhere, by design. Sign-out lives in the admin header and no account settings screen was invented ahead of the design.
- Components are filed by flow: `src/components/guest`, `src/components/speaker`, `src/components/admin`, `src/components/auth`, with everything used by more than one flow at `src/components/` root — `logo-lockup.tsx`, `PlayTarget`, `LevelMeter`, `LiveDot`, `LiveBadge` (whose `showDot={false}` is the same chip carrying a name rather than a state), `AppHeader`, `ConnectionLine`, `ConfirmDialog`, `MICRO_LABEL` (the uppercase micro-label, a class constant rather than a component because its call sites apply it to three different elements) and `Pin` (a PIN shown as digits; a PIN inside a sentence keeps `formatPin` directly). The second flow that needs a component moves it to the root rather than importing across. All of it is hand-written, deliberately outside `components/ui`, and none of it is a `packages/client-core` candidate.
- One non-trivial product component per `.tsx` file. A full screen, stateful form, mutation owner, or independently reusable view gets its own named-export file even when only one parent imports it. Small private render helpers may stay with their owner; small compound families such as guest-message helpers may stay together. Generated shadcn compound primitives under `components/ui` are exempt. Do not create feature barrel files to hide the resulting direct imports.
- `src/lib/audio` is the web-only capture and playback-routing layer, not a `packages/client-core` candidate: `level.ts` owns RMS, decibel mapping, status thresholds and meter motion; `devices.ts` owns pure input/output list shaping; `preferences.ts` owns the microphone preference type, capture-constraint and gain mappings, defaults, and tolerant parse/serialize; `output.ts` owns the stored output-device helpers; `volume.ts` owns the listener-volume range, persistence format and mute transitions; `use-audio-preferences.ts`, `use-audio-output.ts` and `use-audio-volume.ts` own their browser-global storage; `use-audio-sink.ts` applies the selected output to a media element; and `use-mic-capture.ts` owns input devices, streams, and one `AudioContext`/`AnalyserNode` per stream. The four microphone preferences live as one `linguacast-audio-preferences` object. They are unversioned and parsed/defaulted field by field against `DEFAULT_AUDIO_PREFERENCES`. Echo cancellation defaults to and emits explicit `false`. Stored microphone values are mount-time defaults, never adopted live; writes merge field by field so another tab cannot revert untouched fields. Do not restore gain below `MIN_RESTORED_GAIN`. Browser auto gain runs before the app's `GainNode`, so enabling it forces that node to unity without discarding the stored manual gain; disabling it restores that value. Open a microphone stream before enumerating because labels are empty before permission, and collapse the browser's duplicate `default`/`communications` aliases while retaining which physical output represents the system default. An alias-only output list remains locked rather than becoming a fake selectable device. One output-device ID lives under `linguacast-audio-output`. It is only a remembered candidate: browsers with `selectAudioOutput()` must re-authorise it from a user gesture and may return a rotated ID before `setSinkId()` can use it. Null output selection means follow the system default. Listener volume lives separately under `linguacast-audio-volume`, defaults to 70%, spans 0–100%, and applies through the listener media element on every browser; zero persists, while its previous non-zero restore value lasts only for the mounted room. Release capture only through the path that stops tracks and closes the context. Meter values and thresholds are positions on the `METER_FLOOR_DB`-to-full-scale decibel scale, never raw amplitude. Use `getFloatTimeDomainData`, never the 8-bit byte API. The fill uses a timestamp-driven one-pole filter (`ATTACK_MS` 20, `RELEASE_MS` 280); `levelStatus` and `data-peaking` instead use a decaying peak-hold of raw RMS (`HOLD_DECAY_MS`) so short peaks remain visible. `speaker-studio.tsx`'s `SIGNAL_POLL_MS` latch also stays raw so smoothing cannot delay Go live.
- Chrome's permission prompt is invisible to an agent driving the browser through the devtools MCP: a click that trips `getUserMedia` returns success and the screen never changes. Ask the human to grant it before driving the studio — `docs/solutions/workflow-issues/browser-permission-prompts-stall-the-agent-silently.md`.
- Listener counts are settled: a listener is a guest holding an open, locally unpaused consumer on the channel's producer — someone receiving audio, not someone with a page open (`Listening` in `CONCEPTS.md`). The count therefore exists on the speaker studio and on the admin event detail, and **no guest surface carries one at all** — the design's guest placeholders were removed rather than parked, and the studio's pre-flight screen shows no count and no promise of one, because the number is structurally zero before a producer exists. The layouts still hold the slot wherever a count can toggle, so a state change is a data change and never a re-layout: `OnAirStats` renders its Listeners tile ungated (a muted interpreter still has listeners), and the admin channel row always renders its live line. `InputLevelPanel` carries no note at all — it was the one slot whose copy had to be reasoned about per broadcast state, and dropping it removed both the reasoning and the height it reserved. The guest Audio surface is always present for listener volume; its output section exists only where `setSinkId` is available, and follows the system default until the listener makes an explicit choice. The system-default row names the physical device but clears the explicit sink, and that physical device is not repeated as another row. The nine-bar waveform is real (`components/connection-line.tsx`, graded from WebRTC statistics by `lib/media/stats.ts`), and liveness is a producer rather than a page being open.
- No copy on either public screen may claim that anybody is hearing audio unless a producer exists. `broadcastState` and `listenState` are where that property is enforced, and both carry tests for it — keep it when editing either screen.
- The admin surfaces never use `live`, `live-muted` or `live-foreground`: they express enabled instead — the status column, the channel pill and the pulse dot — the dot is dropped rather than recoloured, and an enable switch's checked track is `foreground`. Liveness reaches the admin as words, never as a repainted pill: the events list's status column reports how many of an event's channels are on air and the event detail reports listeners per channel, both from `GET /admin/live` polled at 5s. Admin polls rather than opening a socket because the handshake gate authorizes on a PIN, which the admin does not have, and a socket variant would have to be redesigned when authentication lands; the route sits under `/admin` so that middleware covers it for free. Live state stays out of the admin DTOs — `AdminLiveEvent` is its own schema and its own cache entry, because `admin-queries.ts`'s optimistic patches rewrite `AdminEventDetail` field by field and a poll folded into it would fight a toggle in flight. A failed or pending poll degrades to the idle copy: the admin screens must never fail to load because media is down. The events table is a list of CSS-grid rows rather than a `<table>`, which is why there is no `components/ui/table.tsx`. Creating an event lands on its detail page, not back on the list.
- Dark `--destructive-muted` and `--destructive-border` are rebuilt in `index.css` on the dark `destructive` hue rather than transcribed from the handoff, which copies the `live-muted` and `border` values there. Dark `--accent` is likewise lifted off the handoff's card value to the `border` step, because its only role is a popover's highlighted row and the handoff's value equals `--popover`. Those are the two places the transcription deviates.
- `apps/server/src/db` — better-sqlite3 + Drizzle. `client.ts` holds the `createDb(path)` factory and must stay free of import side effects; `index.ts` holds the `db` singleton and opens a file at module scope. `testing.ts` imports the factory, never the singleton, or loading the test helper would provision `./data/linguacast.db` on every test run. Handlers `import { db }`; there is no dependency injection and none is wanted.
- Migrations are generated, reviewed and committed under `src/db/migrations`. Run `pnpm -F @linguacast/server db:generate` after any change to `schema.ts`, read the SQL, commit it. `drizzle-kit push` is rejected — it leaves nothing in git. There is deliberately no `db:migrate` script: `runMigrations(db)` runs in `index.ts` before `serve()`, so the operator's upgrade procedure is "pull and restart". `apps/server/src/db/migrations` is excluded from Biome — drizzle-kit rewrites its JSON metadata without a trailing newline on every generate.
- `migrate.ts` resolves its folder against `import.meta.dirname`; `DATA_DIR` resolves against the working directory. Migrations are a build artifact and travel with the bundle (`scripts/copy-migrations.mjs` places them at `dist/migrations`); the database is user data and would be destroyed by every redeploy if it lived in `dist/`.
- The four pragmas in `createDb` are all non-defaults, and `foreign_keys` is per-connection — unset, constraints are silently inert, which is why it carries a test. `data/` is gitignored, so the factory's `mkdirSync` is what makes the first `pnpm dev` on a fresh clone work.
- `better-sqlite3` is `false` in `pnpm-workspace.yaml`'s `allowBuilds`. Do not run `pnpm approve-builds` for it — `docs/solutions/integration-issues/decline-the-inferred-native-build-for-better-sqlite3.md`. `mediasoup` sits directly below it as `true`, which looks like an inconsistency and is not: its postinstall *downloads* the prebuilt worker binary rather than compiling one, so blocking it yields no worker at all instead of a slower build.
- `drizzle-zod` is deliberately absent. Row types come from `$inferSelect` / `$inferInsert`. A row is not a DTO, and API schemas are never derived from tables.
- The domain tables are `events` and `channels`. Both default to disabled; there is no lifecycle column. `pin` and `speaker_code` are regenerable natural keys and therefore never primary keys. A channel's `slug` is immutable after creation and is unique only within its event, via the composite `channels_event_id_slug_unique`. The throwaway `meta` table was dropped by migration `0001`; its `0000` migration stays in history rather than being rewritten.
- The admin events list returns each event with its channels — a `listChannels` per event. Deliberate at this deployment's scale, not an accidental N+1.
- 404 parity is a rule: a disabled event, a disabled channel and a nonexistent PIN produce byte-identical responses, enforced by a test in `http/routes/events.routes.test.ts`. The channel lookup checks existence before the speaker code. Failed public lookups are rate limited by an in-memory per-IP token bucket (burst 20, refill 1/s) with a smaller global budget behind it, charged on 404 responses only. Reasoning: `docs/solutions/conventions/identical-404s-for-disabled-and-nonexistent-resources.md`.
- `apps/server/src/testing/api.ts` sets `DATA_DIR` before *dynamically* importing `../db`. `env.ts` parses `process.env` at module load and `db/index.ts` opens a file at module scope, so a static import would provision the real `./data/linguacast.db` when the tests run.
- The socket endpoint is `path: '/api/socket.io'` on the default namespace — a path, not a namespace, so one Vite proxy rule and one reverse-proxy rule cover both the API and the socket. Socket.IO attaches at the `http.Server` level and intercepts that path before Hono sees it, which is invisible from `app.ts`.
- There is no compile-time exhaustiveness for socket handlers. Adding an event to `clientToServer` without registering a handler compiles and surfaces at runtime as an immediate `unknown_event` ack. This is the price of per-call registration, not a defect.
- Register handlers with `on(socket, 'event', fn)` from `socket/lib/on.ts`, never `socket.on` directly: `handle` needs the event name for its watchdog log. It is a plain function, not a registry, and the cast inside it is confined to that one line.
- The handshake carries `{ clientVersion, pin, speakerCode? }` and `authorizeHandshake` makes the whole connection-time decision. It is synchronous on purpose: better-sqlite3 is, so the busy check and the presence claim that follows cannot interleave with another socket's. Claiming the channel is that function's side effect on the success path; `presence.release` on disconnect is the matching half and the only one. The claim is keyed on the **speaker code**, not the socket id — keyed on the socket, a reconnecting interpreter races their own dying socket and is refused for the ten-second ping window. So the same code takes the channel over and `authorizeHandshake` returns `displacedSocketId` beside its data; a *different* code still gets `channel_busy`.
- Event and channel rooms are nested, not alternatives. A listener on the selector is in the event room only; a listener in a channel is in both. Aggregate updates (`channel:status`) fan out to the event room; per-channel signalling goes to the channel room. Membership is re-established in the connect handler rather than the gate, because Socket.IO replays the auth payload on reconnect.
- The broadcast claim lives in memory in `core/presence.ts`, never SQLite: a boolean column drifts from reality on any crash. It is not liveness — it is taken when the studio connects, which may be long before any audio exists.
- Socket validation is asymmetric by rule: the server parses everything arriving from a client; the client trusts the server. Version drift is handled once, at connection time, by the handshake gate.
- The client socket sets `ackTimeout: 10_000` and must never set `retries` — that enables replay, and signalling operations are not idempotent. The server's `HANDLER_TIMEOUT_MS` is 8s, deliberately below the client's ack deadline, so a wedged handler yields a real `timeout` ack.
- The public Socket.IO lifecycle distinguishes `lost` from `connecting`: a retryable disconnect shows "Connection lost", the manager's `reconnect_attempt` advances it to "Reconnecting…", and a successful `connect` dismisses the toast. A `connect_error` is retryable only while Socket.IO's `socket.active` remains true; a handshake refusal and `io server disconnect` are terminal errors. Mediasoup health remains separate from this toast until its presentation is designed.
- Route paths are declared without the `/api` prefix; the prefix lives in the document's `servers` entry and the server's mount point.
- `packages/contract/openapi.json` and `src/generated/api.d.ts` are generated and committed. Run `pnpm gen` after any schema or route change; CI fails on drift.
- The media layer's settled shape: one router per event and never per channel, because a transport can only consume producers on its own router — that is what makes a guest's language switch a consumer swap rather than a renegotiation. Nothing is piped between routers, so one event is capped at one CPU core; the worker pool exists for crash isolation, not throughput. A room is created by a produce and by nothing else, and torn down after a grace period once it holds no producers and no transports. A worker that cannot start at boot is fatal; one that dies later is not.
- Media state is process memory and is never persisted, so a reconnection and a server restart are indistinguishable to a client: every `connect` discards every held identifier and renegotiates from capabilities. A client rebuilds a transport only on `failed`, never on `disconnected`, and a socket connect always supersedes a rebuild in flight. A speaker records the effective mute state when Socket.IO drops and re-produces with the same `paused` value after reconnect; recovery must never force an unmuted speaker to muted or unmute a speaker who was already muted.
- `TRUSTED_PROXY_IPS` is the only environment variable this admin account work adds: optional, comma-separated, unset by default.
- `DATA_DIR` is the one variable naming user data, and both files that are user data live under it — `linguacast.db` and `admin.json`. Each filename sits with its owner (`db/index.ts` and `core/auth/credentials.ts`); there is no separate variable for the credential file, because recovery is deleting one file in the directory the operator already mounts. `MEDIA_STUN_URL` carries a public default rather than being optional: a deployment shipping without STUN fails for exactly the guests least able to diagnose it. Empty means off, which is why it parses as a defaulted string trimmed to `undefined` rather than as `.optional()`.
- The media environment variables are `PUBLIC_ADDRESS`, `MEDIA_LISTEN_IP`, `MEDIA_RTC_PORT_BASE`, `MEDIA_MAX_WORKERS`, `MEDIA_ROOM_IDLE_GRACE_MS` and the optional `MEDIA_STUN_URL` / `MEDIA_TURN_URL` / `MEDIA_TURN_SECRET`. Worker *i* binds one port at base + *i*, on UDP and TCP alike, so the operator forwards a fixed number of ports that does not vary with audience size. `PUBLIC_ADDRESS` is required in production and has no safe default — a wrong one yields well-formed ICE candidates nobody can reach and errors nowhere, which is why startup logs it. It is named for the operator's concept, not the protocol's: it carries no `MEDIA_` prefix because the question it answers is "where is this server", and operator-facing text (`.env.example`, `docs/hosting.md`, every boot log and error) must never say "announced address" or "ICE candidate" at them. Internally the value stays `announcedIp`, which is what it is once it reaches mediasoup. TURN takes a shared secret and credentials are minted per session; a standing credential handed to every guest is an open relay.
- `PUBLIC_ADDRESS` may be a hostname, and `core/media/announced-address.ts` resolves it to an IPv4 address at boot — fatally if it cannot, and equally fatally if the name answers only with private or loopback addresses, which under split-horizon DNS inside a container is the same silent failure wearing a different hat — and re-resolves it every minute, so mediasoup only ever announces a literal address. The resolver returns the whole answer set rather than one address: the address in use is kept while the name still answers with it, so a record with several A entries is not read as a move on every poll, and a refresh that returns nothing routable is treated as a failed lookup rather than an address change. Only one refresh runs at a time, and `WorkerPool.setAnnouncedAddress` serializes moves, so two changes cannot interleave their rebuild passes. Firefox discards a remote ICE candidate naming a host (Mozilla bug 1713128) and mediasoup is ice-lite, so it never sends the check that would form a peer-reflexive candidate instead: an unresolved hostname is a deployment where Chrome works and Firefox is silent, with no error anywhere. A moved address rebuilds each worker's `WebRtcServer` — `announcedAddress` is fixed at its creation and the old one holds the port — and drops that worker's rooms, which reaches clients as `media:reset` with reason `address_changed`, the same recovery a dead worker gets. There is deliberately no escape hatch for announcing the hostname verbatim: it only helps when the *client's* resolver knows better than the server's, which is the split-horizon case `docs/hosting.md` already calls a router problem, and it costs every Firefox guest their audio. An operator whose own DNS view is wrong sets `PUBLIC_ADDRESS` to the literal address, which the STUN cross-check names for them. Reasoning: `docs/solutions/integration-issues/announce-a-resolved-address-because-firefox-drops-hostname-ice-candidates.md`.
- Node 24 (active LTS), pinned in `.nvmrc` and floored by `engines.node`. Stay on LTS: mediasoup is a native addon.
- `core/media/reflexive-address.ts` asks a STUN server what it sees this host as, once at boot, and warns when that disagrees with the announced address. It is a cross-check and never a source: a binding request reports where *outbound* traffic exits, which legitimately differs from where guests arrive behind a multi-WAN router, CGNAT, or a proxy on another host — so auto-discovering the announced address from it would replace a loud boot failure with the same silent unreachable-candidate deployment the announced address exists to prevent. The probe is fire-and-forget (nothing awaits a third party during boot), skipped when the address is already known unroutable, and off unless `probeReflexiveAddress` is passed, which only `index.ts` does — a test must never send a datagram. It binds an ephemeral port because the RTC ports are held, so only the address is ever compared; under endpoint-dependent mapping the port would differ from a worker's while the address still matches.
- `Dockerfile`, `.dockerignore`, `compose.yaml`, `.env.example`, `docker/entrypoint.sh` and `.github/workflows/release.yml` are the deployment artifact; `docs/hosting.md` is its operator-facing half and the only other tracked file under `docs/`. The image compiles once on `$BUILDPLATFORM` — the bundle and the SPA are architecture-independent — and installs only the two tsdown externals per `$TARGETPLATFORM` from the manifest `scripts/emit-runtime-manifest.mjs` generates. The mediasoup worker is fetched explicitly there against a pinned `MEDIASOUP_WORKER_KERNEL`, not left to the postinstall: that names its asset after the *installing* host's kernel major, and each asset targets that kernel's era of glibc — the kernel7 build needs glibc 2.38 and will not load on bookworm, so an image's worker would otherwise depend on which machine built it. Exit status 41 is mediasoup's own signal that a prebuilt binary ran, which is why the build asserts on it. The entrypoint owns `/data` and drops privileges with `setpriv` (util-linux, already in the base) unless Docker's own `user:` directive already made it unprivileged. RTC ports are published one-to-one: a remapped port leaves signalling working and audio silently absent, because the port inside the ICE candidate is the one the worker bound. Reasoning for the pinned worker: `docs/solutions/integration-issues/pin-mediasoups-prebuilt-worker-to-a-kernel-line-the-base-image-can-load.md`. Every operator-facing setting lives in `.env.example` and nowhere else, and only a line the operator must actually decide is left uncommented there — `PUBLIC_ADDRESS` and `TRUSTED_PROXY_IPS`, plus `LINGUACAST_VERSION` because Compose interpolates it. A variable at its default is commented out, so the file reads as a list of decisions rather than a list of values — `compose.yaml` reads it through `env_file` and interpolates `LINGUACAST_VERSION` into the image tag, so an upgrade is one edited line rather than a second place to keep in sync. `PUBLIC_ADDRESS` is declared a second time under `environment:` only for its `:?` guard, which fails `docker compose up` by name before a container exists.
- Commands: `pnpm dev` (contract's gen watcher, the server on 3000 under `tsx watch`, Vite on 5173 proxying `/api` to 3000), `pnpm gen`, `pnpm build` (contract gen → web build → server build, itself `tsdown` plus `scripts/copy-migrations.mjs`, then web's `dist` copied into `apps/server/dist/public`), `pnpm typecheck`, `pnpm check`, `pnpm test`. `pnpm typecheck` runs `pnpm gen` first, so a clean `git status` after it *is* the generated-file drift check CI enforces — there is no separate drift command.
- `apps/web`'s test suite is pure-helper only: `vitest.config.ts` there sets the `@` alias and nothing else, with no jsdom and no component rendering, and it does not reuse `vite.config.ts`. A test that needs to render a component is a signal to reconsider the test, not to add jsdom. Tests import `describe`/`it`/`expect` from `vitest` explicitly; do not enable `globals`, which would require `vitest/globals` in a `types` array and break `packages/contract`'s `"types": []`. `*.test-d.ts` files hold compile-time type assertions checked by `pnpm typecheck`, not by Vitest.
- `@hono/zod-openapi` is pinned to exactly `1.4.0`. Do not float it: 1.5.x has broken type declarations that silently degrade every schema type to `any` under `skipLibCheck`.

## Product context

LinguaCast is a self-hosted, open-source simultaneous-interpretation platform for live in-person events; low audio latency is the core requirement. It targets one modest server run by a church or educational institution, a handful of concurrent events, and tens to low hundreds of listeners. Prefer simple operation over scale; horizontal scaling, multi-tenancy, sharding, and cloud-managed dependencies are out of scope.

There is one authenticated Admin. Events own Channels; an Event PIN grants listening, while a per-Channel Speaker code grants broadcasting. Speakers and listeners have no accounts: possession of the link or code is the entire authorization. Preserve that property and question features that appear to need listener identity. `CONCEPTS.md` is the authoritative domain vocabulary.

The server is Node.js with Socket.IO, SQLite/Drizzle, and the audio-only mediasoup SFU; the current client is a React SPA. Expo/React Native is planned, so keep the API portable beyond browsers.
