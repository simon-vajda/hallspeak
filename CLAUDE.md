# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Status

Specs A through E are implemented: the pnpm workspace, the contract, the API, SQLite persistence, the Zod-validated Socket.IO transport, and the socket connection lifecycle. Every screen is built to the design, in both themes and at both widths, and the admin routes are unauthenticated like the API behind them. `apps/web` carries the handoff's light and dark token blocks, Space Grotesk, and a 20px card radius.

There is no mediasoup and no audio crosses the network. On the guest and speaker screens the REST lookups, the socket liveness feed, microphone enumeration and the input level meter work; playback, going live, mute and the audio-processing preferences are client-local state that emits nothing. Each is commented where the signalling will go — do not wire one to a socket event that does not exist yet.

Keep this file current as decisions are made.

## Layout and commands

- `packages/contract` — hand-written Zod schemas and `createRoute()` definitions. Never built: every export points at TypeScript source and consumers compile it. `src/socket` holds the socket event contract behind the `./socket` subpath export and is **not** re-exported from the root barrel, which pulls in Hono via `./openapi`; browser clients import `@linguacast/contract/socket`. `src/schemas/patterns.ts` holds the bare regexes (`PIN_PATTERN`, `SLUG_PATTERN`, `SEMVER_PATTERN`) behind `./patterns` on the same terms. The contract imports neither `socket.io` nor mediasoup. Its tsconfig sets `"types": []` with no DOM (the React Native seam): a `node:` or DOM import in `src` must fail to compile.
- `tools/openapi-codegen` — a private package whose only job is holding `typescript@5.9.3` and exposing an `openapi-codegen` bin; `packages/contract` depends on it. Every real package pins `typescript@7.0.2`, and TypeScript 5 must remain unreachable as a binary from any package that compiles source — `pnpm why -r typescript` is the mechanical check. Reasoning and exit condition: `docs/solutions/architecture-patterns/isolate-a-legacy-compiler-behind-a-codegen-tool-package.md`.
- `apps/server` — Hono + `@hono/zod-openapi`. `app.ts` builds the app without listening; `index.ts` owns the listener. `defaultHook` must be passed to *every* `OpenAPIHono` instance that registers routes — it is not inherited by sub-apps.
- `apps/server/src` is split by dependency direction. `core/` is the domain: it must not import `hono`, `@hono/zod-openapi` or `socket.io`, and must not reach sideways into `http/` or `socket/`, but it may import `drizzle-orm`, `better-sqlite3` and later `mediasoup`. `http/` holds every Hono-coupled module; `socket/` every Socket.IO-coupled one, split into `socket/lib/` for plumbing and `socket/handlers/` for per-feature events. `lib/` is what has neither domain knowledge nor transport coupling — `problem.ts`, `rate-limit.ts`, `semver.ts`. `db/` keeps its own conventions. The boundary is enforced by `core/boundary.test.ts`, a source-text scan that fails on a forbidden specifier, relative paths included: `docs/solutions/architecture-patterns/guard-a-layer-boundary-with-a-self-testing-import-scan.md`. File a module by what it is, not by the directory its only consumer occupies.
- Directories name the role; filenames name the entity plus a role suffix — `.service.ts`, `.mapper.ts`, `.routes.ts`, `.middleware.ts`, `.handlers.ts`. A module whose stem is already unique and role-descriptive takes no suffix: `codes.ts`, `access.ts`, `presence.ts`, `handshake.ts`, `on.ts`, `rooms.ts`, `types.ts`. Tests stay colocated as `<module>.test.ts`.
- Where mediasoup lands is decided: room, transport and producer state in `core/media/`; its signalling handlers in `socket/handlers/`; `core/presence.ts` absorbed into `core/media/` when `isOnline` starts meaning "audio is flowing". Events originating inside `core/` reach clients through a typed subscribe registry `core/` owns — `core/media/` exports a subscribe function over a discriminated union of events, and `socket/index.ts` subscribes at attach and does the room fan-out. Nothing is injected into `core/`, and no handler registry maps event names to handlers as data.
- `apps/web` — Vite 8 + React 19 SPA. TanStack Router with file-based routing: a file under `src/routes/` *is* a route, and the Vite plugin regenerates `src/routeTree.gen.ts` on dev-server startup and on every change there. Nest routes as directories, not dotted filenames — `routes/admin/events/$id.tsx` — and a directory's layout route is its `route.tsx`. `routeTree.gen.ts` is generated, committed, and excluded from Biome. `tsconfig.json` must not declare `baseUrl`; TypeScript 7 removed it, and `paths` alone resolves for both `tsc` and the shadcn CLI. `src/api`, `src/socket` and `src/state` are the portable directories that lift into `packages/client-core` when the Expo app begins; everything else under `apps/web/src` is web-only. `src/lib/socket.ts` exports `connectSocket(auth)`, not a module singleton: the handshake carries the event's PIN, so one socket per page is required.
- `src/components/ui` is the shadcn CLI's target: add and update components with `pnpm dlx shadcn@latest add <name>` from `apps/web`, then `pnpm check:fix`. Deliberate customisations are allowed there but each must be recorded in this list, because a later `add` silently drops it. Current customisations: `button.tsx` carries a `pill` size (`h-12 rounded-full px-6 text-base font-semibold`); `switch.tsx` carries an `lg` size (46×27 with a 21px thumb, its padding and checked offset written out because the CLI's `calc(100%-2px)` only centres the thumb at the default size's proportions); `select.tsx`'s trigger and `slider.tsx`'s thumb carry `cursor-pointer`; `sonner.tsx` imports `useTheme` from `@/components/theme-provider`, not `next-themes`. `add` will offer to overwrite `button.tsx` when it is pulled in as a dependency of another component (`sheet` does this) — decline that prompt. Prefer call-site classes for one-off styling. `biome.json` turns six lint rules off for that directory only (four `a11y`, `noArrayIndexKey`, `noDoubleEquals`); do not hand-fix generated files. Reasoning: `docs/solutions/conventions/customising-generated-shadcn-components.md`.
- The design's off-scale values go on the Tailwind scale, not into arbitrary utilities: the spacing scale derives from `--spacing`, so 26px is `6.5`, 18px is `4.5`, 1120px is `280`. Two values are named in `index.css`: `--spacing-gutter` (the 26px screen gutter, `px-10` from `lg`) and `--spacing-shell` (the 1120px admin cap). The type ramp is six `--text-*` entries — `text-screen`, `text-screen-lg`, `text-section`, `text-label`, `text-meta`, `text-note` — each carrying its own weight and line-height plus tracking where the design fixes one; body text is `text-sm`. `text-[18px]` is still loose across two admin files and is the next candidate for the ramp. The animations are `--animate-pulse-live`, `--animate-ring` and `--animate-ring-delayed`, all held at a resting frame under `prefers-reduced-motion` rather than removed. Where the canvas and the handoff prose disagree on an animation value, the canvas wins. Arbitrary values remain right for one-off type sizes and grid templates. Colours are never written at a call site: they are `--color-*` tokens in `index.css`, referenced by role (`text-muted-foreground`, `border-destructive`), never as a hex and never as a role borrowed to mean something else. Procedure for a new value: `docs/solutions/conventions/design-values-onto-the-scale.md`.
- Components are filed by flow: `src/components/guest`, `src/components/speaker`, `src/components/admin`, with everything used by more than one flow at `src/components/` root — `logo-lockup.tsx`, `PlayTarget`, `LevelMeter`, `LiveDot`, `LiveBadge`, `AppHeader`, `ConnectionLine`, `ConfirmDialog` (which carries the dialog ramp constants). The second flow that needs a component moves it to the root rather than importing across. All of it is hand-written, deliberately outside `components/ui`, and none of it is a `packages/client-core` candidate.
- `src/lib/audio` is the capture layer: `level.ts` (pure RMS and the quiet/good/peaking mapping, with the 0.85 clip threshold as its named constant), `devices.ts` (pure list shaping) and `use-mic-capture.ts` (`enumerateDevices`, `getUserMedia`, one `AudioContext`/`AnalyserNode` per stream). It is web-only and not a `packages/client-core` candidate. Two constraints drive the pure halves' tests: device labels come back empty until permission has been granted at least once, so the order is open-a-stream-then-enumerate; and the browser lists the system default a second time as a `default`/`communications` alias. Release every capture through the one path that stops the tracks and closes the context.
- Chrome's permission prompt is invisible to an agent driving the browser through the devtools MCP: a click that trips `getUserMedia` returns success and the screen never changes. Ask the human to grant it before driving the studio — `docs/solutions/workflow-issues/browser-permission-prompts-stall-the-agent-silently.md`.
- Four deliberate deviations from the design canvas on the guest and speaker screens. (1) Every count is omitted rather than faked; the layouts hold the slot, so a count arrives as a data change rather than a re-layout. (2) The nine-bar "Good connection" waveform is a real socket-status line (`components/connection-line.tsx`). (3) The "Play to · AirPods Pro" output-device card is not built — `setSinkId` is Chromium-only and needs a playing `<audio>` element, so it belongs with playback. (4) `isLive` in the speaker studio is `useState` and nothing else; the presence claim happens at the handshake, so guests see a channel as live when the studio page opens. No copy asserts that anybody is hearing audio — keep that property when editing it.
- The admin surfaces never use `live`, `live-muted` or `live-foreground`: liveness is not modelled yet, so the status column, channel pill and pulse dot express enabled instead, the dot is dropped rather than recoloured, and an enable switch's checked track is `foreground`. The events table is a list of CSS-grid rows rather than a `<table>`, which is why there is no `components/ui/table.tsx`. Creating an event lands on its detail page, not back on the list.
- Dark `--destructive-muted` and `--destructive-border` are rebuilt in `index.css` on the dark `destructive` hue rather than transcribed from the handoff, which copies the `live-muted` and `border` values there. Dark `--accent` is likewise lifted off the handoff's card value to the `border` step, because its only role is a popover's highlighted row and the handoff's value equals `--popover`. Those are the two places the transcription deviates.
- `apps/server/src/db` — better-sqlite3 + Drizzle. `client.ts` holds the `createDb(path)` factory and must stay free of import side effects; `index.ts` holds the `db` singleton and opens a file at module scope. `testing.ts` imports the factory, never the singleton, or loading the test helper would provision `./data/linguacast.db` on every test run. Handlers `import { db }`; there is no dependency injection and none is wanted.
- Migrations are generated, reviewed and committed under `src/db/migrations`. Run `pnpm -F @linguacast/server db:generate` after any change to `schema.ts`, read the SQL, commit it. `drizzle-kit push` is rejected — it leaves nothing in git. There is deliberately no `db:migrate` script: `runMigrations(db)` runs in `index.ts` before `serve()`, so the operator's upgrade procedure is "pull and restart". `apps/server/src/db/migrations` is excluded from Biome — drizzle-kit rewrites its JSON metadata without a trailing newline on every generate.
- `migrate.ts` resolves its folder against `import.meta.dirname`; `DATABASE_PATH` resolves against the working directory. Migrations are a build artifact and travel with the bundle (`scripts/copy-migrations.mjs` places them at `dist/migrations`); the database is user data and would be destroyed by every redeploy if it lived in `dist/`.
- The four pragmas in `createDb` are all non-defaults, and `foreign_keys` is per-connection — unset, constraints are silently inert, which is why it carries a test. `data/` is gitignored, so the factory's `mkdirSync` is what makes the first `pnpm dev` on a fresh clone work.
- `better-sqlite3` is `false` in `pnpm-workspace.yaml`'s `allowBuilds`. Do not run `pnpm approve-builds` for it — `docs/solutions/integration-issues/decline-the-inferred-native-build-for-better-sqlite3.md`.
- `drizzle-zod` is deliberately absent. Row types come from `$inferSelect` / `$inferInsert`. A row is not a DTO, and API schemas are never derived from tables.
- The domain tables are `events` and `channels`. Both default to disabled; there is no lifecycle column. `pin` and `speaker_code` are regenerable natural keys and therefore never primary keys. A channel's `slug` is immutable after creation and is unique only within its event, via the composite `channels_event_id_slug_unique`. The throwaway `meta` table was dropped by migration `0001`; its `0000` migration stays in history rather than being rewritten.
- The admin events list returns each event with its channels — a `listChannels` per event. Deliberate at this deployment's scale, not an accidental N+1.
- 404 parity is a rule: a disabled event, a disabled channel and a nonexistent PIN produce byte-identical responses, enforced by a test in `http/routes/events.routes.test.ts`. The channel lookup checks existence before the speaker code. Failed public lookups are rate limited by an in-memory per-IP token bucket (burst 20, refill 1/s) with a smaller global budget behind it, charged on 404 responses only. Reasoning: `docs/solutions/conventions/identical-404s-for-disabled-and-nonexistent-resources.md`.
- `apps/server/src/testing/api.ts` sets `DATABASE_PATH` before *dynamically* importing `../db`. `env.ts` parses `process.env` at module load and `db/index.ts` opens a file at module scope, so a static import would provision the real `./data/linguacast.db` when the tests run.
- The socket endpoint is `path: '/api/socket.io'` on the default namespace — a path, not a namespace, so one Vite proxy rule and one reverse-proxy rule cover both the API and the socket. Socket.IO attaches at the `http.Server` level and intercepts that path before Hono sees it, which is invisible from `app.ts`.
- There is no compile-time exhaustiveness for socket handlers. Adding an event to `clientToServer` without registering a handler compiles and surfaces at runtime as an immediate `unknown_event` ack. This is the price of per-call registration, not a defect.
- Register handlers with `on(socket, 'event', fn)` from `socket/lib/on.ts`, never `socket.on` directly: `handle` needs the event name for its watchdog log. It is a plain function, not a registry, and the cast inside it is confined to that one line.
- The handshake carries `{ clientVersion, pin, speakerCode? }` and `authorizeHandshake` makes the whole connection-time decision. It is synchronous on purpose: better-sqlite3 is, so the busy check and the presence claim that follows cannot interleave with another socket's. Claiming the channel is that function's side effect on the success path; `presence.release` on disconnect is the matching half and the only one. First connection wins; a latecomer gets `channel_busy` and the incumbent is never disturbed.
- Event and channel rooms are nested, not alternatives. A listener on the selector is in the event room only; a listener in a channel is in both. Aggregate updates (`channel:status`) fan out to the event room; per-channel signalling goes to the channel room. Membership is re-established in the connect handler rather than the gate, because Socket.IO replays the auth payload on reconnect.
- Speaker presence lives in memory in `core/presence.ts`, never SQLite: a boolean column drifts from reality on any crash. `isOnline` currently means "a socket is connected", not that audio is flowing, and must be replaced by mediasoup transport state. The comment in that file is the marker; the UI, the broadcast and the client subscription all survive the swap.
- Socket validation is asymmetric by rule: the server parses everything arriving from a client; the client trusts the server. Version drift is handled once, at connection time, by the handshake gate.
- The client socket sets `ackTimeout: 10_000` and must never set `retries` — that enables replay, and signalling operations are not idempotent. The server's `HANDLER_TIMEOUT_MS` is 8s, deliberately below the client's ack deadline, so a wedged handler yields a real `timeout` ack.
- Route paths are declared without the `/api` prefix; the prefix lives in the document's `servers` entry and the server's mount point.
- `packages/contract/openapi.json` and `src/generated/api.d.ts` are generated and committed. Run `pnpm gen` after any schema or route change; CI fails on drift.
- Node 24 (active LTS), pinned in `.nvmrc` and floored by `engines.node`. Stay on LTS: mediasoup is a native addon.
- Commands: `pnpm dev` (contract's gen watcher, the server on 3000 under `tsx watch`, Vite on 5173 proxying `/api` to 3000), `pnpm gen`, `pnpm build` (contract gen → web build → server build, itself `tsdown` plus `scripts/copy-migrations.mjs`, then web's `dist` copied into `apps/server/dist/public`), `pnpm typecheck`, `pnpm check`, `pnpm test`. `pnpm typecheck` runs `pnpm gen` first, so a clean `git status` after it *is* the generated-file drift check CI enforces — there is no separate drift command.
- `apps/web`'s test suite is pure-helper only: `vitest.config.ts` there sets the `@` alias and nothing else, with no jsdom and no component rendering, and it does not reuse `vite.config.ts`. A test that needs to render a component is a signal to reconsider the test, not to add jsdom. Tests import `describe`/`it`/`expect` from `vitest` explicitly; do not enable `globals`, which would require `vitest/globals` in a `types` array and break `packages/contract`'s `"types": []`. `*.test-d.ts` files hold compile-time type assertions checked by `pnpm typecheck`, not by Vitest.
- `@hono/zod-openapi` is pinned to exactly `1.4.0`. Do not float it: 1.5.x has broken type declarations that silently degrade every schema type to `any` under `skipLibCheck`.

## What LinguaCast is

A self-hosted, open-source platform for simultaneous interpretation at live in-person events — church sermons, international conferences, talks. An interpreter speaks into their phone or laptop; guests in the room listen live on their own devices. Low audio latency is the core product requirement.

## Deployment context (drives most design decisions)

Deployed on small servers run by churches and educational institutions, not in a central cloud. Expected load: a handful of concurrent events, listeners in the tens to low hundreds. Optimize for simplicity of operation and setup over scalability. Horizontal scaling, multi-tenancy, sharding, and cloud-managed dependencies are explicitly out of scope. A single-process server that an admin can run on modest hardware is the target.

## Domain model

- **Admin** — the only authenticated account in the system. Single user. Creates and edits events, manages app settings, shares links.
- **Event** — e.g. "Sunday Service". Owns one or more channels.
- **Channel** — typically a target language, e.g. "English", "Spanish". One speaker, many listeners.
- **Speaker code** — generated per **channel**, not per event, and grants broadcasting on that one channel only. The speaker link is the ordinary channel URL plus `?speaker_code=…`, so dropping the query param degrades it into a valid listener URL.
- **PIN** — generated per **event**. Six digits, grants listening, and is what a guest types or a QR code carries.
- **Listener link / QR code** — takes a guest directly to an event; they pick a channel and listen.

## Access model

Only the admin authenticates. Speakers and listeners are authorized purely by possession of their link or code — no accounts, no signup, no login. The friction of authentication would defeat the product. Preserve this property when designing new features; if something seems to need listener identity, question the requirement first.

## Intended stack

- **Server** — Node.js with Socket.IO for signalling and SQLite (better-sqlite3 + Drizzle) for persistence, both implemented, and [mediasoup](https://mediasoup.org/) as the WebRTC SFU (not started). Audio-only.
- **Web frontend** — React SPA. This is the only client for now.
- **Mobile** — likely Expo / React Native, planned but not started. Avoid decisions that would lock the API to a browser-only client.

## Working in this repo

Still open: the mediasoup event set and the room/transport/producer lifecycle, settings storage, and admin authentication — which lands as one middleware on the `/admin` subtree, which is why that prefix exists. Record those here when they are settled rather than leaving them implicit in code.

The whole UI is built and waiting on mediasoup. The client work is small and already sited: the listener's play gesture starts an `AudioContext` and a consumer instead of only flipping `isPlaying`; the speaker's "Go live" produces from the `MediaStreamTrack` `use-mic-capture.ts` already owns; the audio-processing preferences become `MediaTrackConstraints` and a `GainNode` on that graph; the counts drop into the slots the layouts hold open.

`docs/` is local-only scratch — plans, design handoffs and `docs/superpowers` are gitignored on purpose. Never stage them and don't "fix" their absence from git. The exception is `docs/solutions`, which is in git: solutions to past problems, filed by category with YAML frontmatter (`module`, `tags`, `problem_type`). Read it when working in an area it covers.

`CONCEPTS.md` at the repo root is the shared domain vocabulary — entities, named processes and status concepts with a project-specific meaning.
